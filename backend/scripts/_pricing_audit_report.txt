All three providers use identical heuristic usage_variables (100 users, 40 req/user/mo,
same request-share splits, 5 GiB storage, 2.4 GB egress). The gap is caused by
calculation bugs and catalog SKU role mismatches ù not architecture mapping differences
(with one Azure caveat noted below).

--- AWS ($659.55) vs Azure ($48.18) ---

PRIMARY BUG ù AWS AppConfig Experiment Hours ($657.00, 99.5% of AWS total):
  Component: Configuration Management -> AppConfig
  SKU: use1_appconfig_experimenthours
  Quantity: 730 hours (full month, likely defaulted from hours_per_month)
  Unit price: $0.90/hour (AppConfig feature-flag experimentation pricing)
  Cost: 730 x $0.90 = $657.00

  This is a catalog role mismatch / formula bug. A simple config-management component
  for 100 users should NOT bill 730 hours of AppConfig experimentation. Azure's
  equivalent (App Configuration) correctly prices at $1.25/mo using per-day/per-event SKUs.

SECONDARY ISSUES (minor):
  - DynamoDB matched export-data SKU (use1_exportdatasize_bytes) instead of storage/RCU
  - CloudWatch and Amplify Hosting formula evaluation failed ($0)
  - CloudWatch Logs matched CloudFront vended logs SKU ($2.12) ù wrong log class

Without the AppConfig bug, AWS would be ~$2.55û$3.46/mo (consistent with other
project runs for the same app that predate this pricing generation).

--- GCP ($3,570.40) vs Azure ($48.18) ---

PRIMARY BUG ù GCP API Gateway request unit scaling ($3,570.00, 99.99% of GCP total):
  Component: API Gateway -> API Gateway
  SKU: manual-gcp-api-gateway-requests (requests role)
  Quantity: 1,400 requests/month
  Unit price: $3.00 per "1M requests"
  Calculated cost: 1,400 x $3.00 = $3,570.00  <- WRONG

  Correct cost: (1,400 / 1,000,000) x $3.00 = $0.0042
  The linear formula engine multiplies raw request count by the per-million price
  without dividing by 1,000,000. Azure API Management correctly prices 1,400 calls at $0
  (consumption tier within free tier).

--- Azure ($48.18) - likely UNDERPRICED ---

Azure appears cheapest partly due to pricing FAILURES (components priced at $0):
  - User Progress Database -> Azure Cosmos DB: formula evaluation failed ($0)
    (SQL Database is also mapped but never priced as a second service)
  - Notification Hubs: formula failed ($0)
  - Azure Monitor: formula failed ($0)

Azure Log Analytics may OVER-count: both premium ($4.62/GB) and standard ($2.30/GB)
tiers applied to the same 5 GB of logs = $29.41û$39.79 (should pick one tier).

If Cosmos DB/SQL Database were priced (~$30/mo SQL floor), Azure would be ~$78û$88/mo,
still far below the buggy AWS/GCP figures.

--- Architecture mapping note ---

Database component maps to TWO services per provider (e.g., DynamoDB + RDS on AWS,
Cosmos DB + SQL Database on Azure) but only the FIRST listed service is priced per
component. This affects completeness but is NOT the primary cause of the AWS/GCP spike.
